This guide builds a small order-form graph end to end. Start with sync formulas, then add an async data source.

## Sync first — derived state from local fields

```ts
import { createGraph } from "data-compute";

interface OrderForm {
  // source fields (inputs)
  quantity: number;
  unitPrice: number;
  taxRate: number;
  discount: number;
  // derived fields (outputs)
  subtotal: number;
  tax: number;
  total: number;
}

const graph = createGraph<OrderForm>({
  subtotal: (f) => f.quantity * f.unitPrice,
  tax:      (f) => f.subtotal * f.taxRate,
  total:    (f) => f.subtotal + f.tax - f.discount,
});

const result = await graph.compute({
  quantity: 5,
  unitPrice: 20,
  taxRate: 0.1,
  discount: 5,
});

// → { quantity: 5, unitPrice: 20, taxRate: 0.1, discount: 5,
//     subtotal: 100, tax: 10, total: 105 }
```

What happened:

1. **Dependencies were auto-tracked.** When the graph was created, each formula ran once against a Proxy. The Proxy recorded which source fields were read.
2. **Execution was topologically sorted.** `subtotal` runs before `tax`, `tax` before `total`. Order of definition doesn't matter.
3. **A cycle patch was returned.** The input fields and evaluated computed outputs appear in the result.

## Add an async data source

Suppose the tax rate comes from an API instead of being a local input.

```ts
import { createGraph, request } from "data-compute";

interface PricingForm {
  productId: string;
  quantity: number;
  basePrice: number;
  // async source
  taxRate: number;
  // derived
  subtotal: number;
  tax: number;
  total: number;
}

const graph = createGraph<PricingForm>(
  {
    subtotal: (f) => f.quantity * f.basePrice,
    tax:      (f) => f.subtotal * (f.taxRate ?? 0),
    total:    (f) => f.subtotal + f.tax,
  },
  {
    // taxRate is fetched, not provided
    taxRate: request(
      (f) => ({ productId: f.productId }),
      { query: async ({ productId }) => fetchTaxRate(productId) },
    ),
  },
);

const result = await graph.compute({
  productId: "p_1",
  quantity: 5,
  basePrice: 20,
});
// → fetch happens; downstream formulas wait; result includes taxRate, subtotal, tax, total
```

The async node participates in the same DAG as the sync formulas. `tax` automatically waits for `taxRate` before running. If `productId` changes mid-flight, the in-flight request becomes stale and is handled per the configured policy.

## Batched requests

When the backend expects coalesced requests (e.g. one POST with N items instead of N POSTs), use `batchRequest`. Multiple `compute()` calls in the same microtask are coalesced into one query.

```ts
import { createGraph, batchRequest } from "data-compute";

const graph = createGraph<PricingForm>(
  { /* formulas */ },
  {
    pricing: batchRequest(
      (f) => ({ productId: f.productId, quantity: f.quantity }),
      {
        query: async (entries) => {
          const res = await fetch("/api/pricing/batch", {
            method: "POST",
            headers: { "Content-Type": "application/json" },
            body: JSON.stringify(entries.map((e) => e.request)),
          });
          const data = await res.json();
          return entries.map((e, i) => ({ id: e.id, response: data[i] }));
        },
        stalePolicy: "discard-and-retry",
      },
    ),
  },
);
```

## Wire into a state manager

`data-compute` doesn't own state. Provide `getState` and `setState` to keep results in sync with your store.

In the example below, `applyPatch` is your framework or store helper that deep-merges patch paths into the current state.

```ts
const graph = createGraph<OrderForm>(
  { /* formulas */ },
  { /* data sources */ },
  {
    getState: () => store,
    setState: (patch) => applyPatch(store, patch),
  },
);

// Granular patches in, granular patches out.
// applyPatch should deep-merge patch paths into the store.
graph.compute({ quantity: 2 });
```
